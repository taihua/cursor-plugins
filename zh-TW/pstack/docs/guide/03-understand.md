# 改之前，先理解程式碼

去改你不懂的程式碼，正是隱藏的退步（regression）被出貨的原因——對 agent 和對你都一樣。agent 失敗通常有兩種：誤解了你要什麼，或缺少把事情做對的脈絡。[提示詞裡該放什麼](./02-poteto-mode.md#提示詞裡該放什麼) 處理第一種，這一頁處理第二種。

pstack 給你四個入口。`/how` 解釋程式碼**現在**做什麼。`/why` 挖出它**為什麼**長這樣。`/teach` 把兩者融合成一份解釋。`/recall` 重建你自己最近在某個主題上的脈絡。每一個都會逼 agent 用你能檢查的話解釋自己——這就是你監督一個可能比你更懂程式碼的 agent 的方法。

## 從唯讀調查開始

原因不明時，要求「發現」，而不是「修正」：

```text
/poteto-mode 調查為什麼背景工作每隔幾小時就會逾時。告訴我目前知道什麼、你用了哪些資料、以及你最有可能的假設。先不要改任何程式碼。
```

「先不要改任何程式碼」會把這個任務導向[調查劇本](../../skills/poteto-mode/playbooks/investigation.md)。它會跑 `/how`，遇到動機相關的問題再加上 `/why`，最後回傳附出處的解釋。如果是在多個選項之間抉擇，它會給出建議和取捨對照表。問「你用了哪些資料」會讓 agent 把**證據**和**猜測**分開。當調查結果指向某個修正時，把修正當成一個新任務開始。

## 用 `/how` 追蹤行為

```text
/how 我們怎麼去除重複的通知？查詢訂閱者時有沒有 N+1 問題？
```

直接問你真正想問的。[`/how`](../../skills/how/SKILL.md) 會讀程式碼，用資深工程師帶新人認識子系統的程度回答你：執行流程、關鍵型別、不明顯的地方。對大型子系統，它會先派出二到四個唯讀的探索者；對範圍小的問題，它就直接讀、直接解釋。

## 用 `/why` 挖出歷史

```text
/why 重試上限為什麼設成 5？那個理由現在還成立嗎？
```

[`/why`](../../skills/why/SKILL.md) 從版本控制開始，接著平行查詢你的 MCP 提供的各類證據：議題追蹤、長篇文件、團隊聊天、監控、錯誤追蹤、分析數據。報告會標註所有出處，把直接證據和推論分開，紀錄不足時會說「看起來似乎是」。查無結果也會回報，因為「沒有人寫下為什麼」本身就是一個答案。

兩者很自然地能組合。當你懷疑歷史能解釋為什麼程式這麼亂時，「先做 why 再做 how」是個好提示詞。

## 用 `/teach` 真正理解

```text
/teach 教我這個 PR 怎麼改變了重試行為。說服我它修的是根本原因而不是症狀。
```

[`/teach`](../../skills/teach/SKILL.md) 用在摘要不夠的時候。它會跑 `/how` 和 `/why`（小改動可能只跑其中一個），再把發現編織成一份白話解釋，一張圖一張圖地建構起來。「說服我」這種說法很值得重複使用——它把解釋變成一個你可以檢驗的論證，而不只是導覽。

它也可以用在 agent 自己的選擇上：

```text
/teach 教我你為什麼用這種方式實作，而不是用佇列。你做了什麼取捨？為什麼？
```

教學對 agent 的幫助跟對你一樣大。一個必須解釋自己工作的 agent，得真的去讀程式碼，並用證據支持每個主張，而不是自信地說完就走。

## 用 `/recall` 重建你自己的脈絡

```text
/recall 幫我回顧上週的匯出相關工作
```

[`/recall`](../../skills/recall/SKILL.md) 會挖掘你自己最近的聊天，加上共享紀錄（議題、之前的修正、還在發生的錯誤），交回一份「目前狀況和下一步」的簡報。你的舊聊天裡有新 agent 沒有的脈絡，所以要在舊主題上開始新工作時，先載入它，再交給新的輸入：

```text
/recall 我昨天做的虛擬化清單相關工作，然後讀這份 bug 回報。
```

如果你想接續某一個特定的聊天，那是下面的「接手工作」劇本，不是 `/recall`。

## 用「接手工作」劇本接手先前的工作

當另一個 agent（或上週的你）留下一個做到一半的分支：

```text
/poteto-mode 接手這個分支。讀決策紀錄，搞清楚哪些已經完成，然後從那裡繼續。不要重做已完成的工作。
```

[接手工作劇本](../../skills/poteto-mode/playbooks/session-pickup.md) 會把先前的紀錄當作權威來源。它會重建分支狀態和決策、指出從哪裡接續，並對照原始目標驗證繼承下來的說法，而不是全部從頭推導一遍。

**陷阱：** 不要因為「agent 反正會讀程式碼」就跳過這一頁的技能。沒有先建立心智模型就開始改的 agent，往往會在第一個看似合理的地方修掉症狀。先跑 `/how`，比之後再出第二個 bug 便宜。
