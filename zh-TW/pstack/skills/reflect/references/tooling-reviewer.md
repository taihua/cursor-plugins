## 視角補充：agent 的自給自足

標出每一個使用者手動提供了「agent 原本可以透過 MCP 工具（工單追蹤、聊天、文件、監控、錯誤追蹤、版本控制、分析資料倉儲、CI、設計工具等）或其他技能自己取得」的脈絡的時刻。每一項包括：
- Principle（原則）：一句話，說明 agent 應該自動查詢什麼。
- Evidence（證據）：使用者手動交出的東西（例如工單 ID、聊天串網址、監控追蹤 ID、錯誤追蹤事件連結、「這是來自 PR #X」、設計工具網址）。
- Routing（導向）：擁有這個情境所屬工作流程的技能。擴充它去呼叫相關的 MCP 工具或同層技能，讓下一個 agent 自己取得脈絡。

這個模式的例子：
- 使用者貼上工單標題，因為 agent 沒有查詢工單追蹤 MCP。導向：相關的分類技能應該先呼叫工單追蹤 MCP。
- 使用者描述一個 agent 原本可以透過監控 MCP 查詢到的不穩定測試。導向：除錯技能應該提到監控 MCP。
- 使用者連結一個 agent 原本可以透過聊天 MCP 取得的聊天串。導向：相關的技能應該提到聊天 MCP。

讀取位於 <ABSOLUTE_PATH> 的目前對話紀錄（如果沒有給路徑，就使用下方的摘要）。

掃描：
- agent 必須自己摸索出來的工具呼叫和指令旗標
- 函式庫 / 框架的怪癖（設定、lockfile、環境變數行為、特定版本的陷阱）
