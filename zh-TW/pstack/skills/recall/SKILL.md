# Recall（回顧）

**在開始或接續工作之前，你要重建使用者最近的工作脈絡，並交回一份精簡的摘要：目前的狀況，以及下一步該做什麼。**

保持精簡、切題。只讀範圍內的線索需要的東西，然後停下。

你的脈絡存在兩份紀錄中。你自己的聊天紀錄保存了你做了什麼、決定了什麼。共享紀錄則保存了同一段程式碼周圍、以其他名稱發生的所有事：使用者一再回報的症狀、出貨後又被還原的修正、仍在正式環境觸發的錯誤。第二份紀錄就是 **why** 技能會搜尋的地方，橫跨版本控制、議題追蹤、聊天與議題頻道、長篇文件和錯誤追蹤。一個有很長 bug 尾巴的功能，大部分的故事都在那裡，所以不要只從你的對話紀錄去重建它。

對話紀錄位於 `~/.cursor/projects/<slug>/agent-transcripts/<uuid>/<uuid>.jsonl`，其中 `<slug>` 是工作區路徑去掉開頭的斜線、並把每個「/」換成「-」（所以 `/Users/you/proj` 會變成 `Users-you-proj`）。每一行是一則聊天訊息。

1. 先分類，再導向。要接續某一個特定的先前聊天，是 `session-pickup` 劇本，不是這個。把習慣變成一個持久的技能是 `automate-me`。一份給人讀的工作摘要是另一種任務。Recall 是在你行動之前，跨最近的聊天載入工作脈絡。如果使用者已經給了你一份完整的狀態摘要（路徑、分支、改動），就用它，跳過挖掘。
2. 搜尋前先鎖定範圍。固定時間範圍（「最近」是一個真實的範圍，預設最近 7 天）、有指定的話固定主題，以及工作區（預設為目前的工作區。沒被要求的話，永遠不要讀其他專案的對話紀錄）。把範圍複述回去。永遠不要默默把「全部」變成「最近 N 個」。
3. 在你的聊天紀錄中分派。用快速、便宜的模型派出平行的子代理，每個處理語料的一部分。告訴每個子代理：依真實的修改時間（`ls -t`）排序候選，永遠不要依 UUID 名稱排序；先 grep 主題，然後只讀符合的聊天、而且只讀相關的部分；跳過目前的聊天以及明顯的雜訊（子代理、eval 和測試用的聊天）。每個子代理回傳相同的格式，每個聊天一個區塊：主題、使用者的目標、決定、未解決的線索、困難與糾正，以及成品（PR、工單、分支），每一項都引用聊天 UUID。如果只有一兩個聊天，就跳過分派、直接搜尋。原始對話紀錄留在子代理中，主對話只拿到它們的發現。依 **poteto-mode** 技能的「子代理」章節，為每個子代理選擇工作需要的推理等級與快速或標準速度。
4. 只要主題指名了某個功能、檔案、子系統、區域或 bug，就掃過共享紀錄。這是預設行為，不是看情況判斷，而且「我在 X 上的工作」也不能豁免。把它交給 **why** 技能的來源調查者，但把它們的問題從「這為什麼這樣建」轉向「目前的狀態是什麼、試過哪些沒撐住的做法、使用者還在回報什麼」。重用它針對各來源的做法，讓調查者和聊天紀錄的挖掘平行執行，並繼承它的姿態：每個來源一個調查者、查無結果也是發現、跳過不可用的 MCP 並說明。把回來的結果併入簡報。只有在沒有指名目標的純活動回顧（「我這週做了什麼」）時才跳過這一步，那種情況下你自己的紀錄和即時狀態就是全部的答案。
5. 對照即時狀態驗證。把挖掘和掃描中浮現的 PR、分支和工單，用 `git` 和 `gh` 檢查。當答案取決於某個 agent 實際做了什麼（它跑的工具、讀的檔案、遇到的錯誤）時，讀完整的對話紀錄，而不只是一份裁剪過的本機副本。
6. 依下面的格式寫簡報。依線索分組。保持在指定的主題上。

## 輸出格式

先放摘要，然後是線索狀態，然後是問題，最後是下一步。更深入的細節放在下面，或直接砍掉。

- **摘要（Capsule）。** 最多 5 個項目。這份工作是什麼，以及整體狀況如何。
- **線索（Threads）。** 每條一行，前面加上恰好一個狀態標籤：`[merged #N]`（已合併）、`[open PR #N]`（PR 開啟中）、`[in flight <branch>]`（進行中）、`[verified, uncommitted]`（已驗證、未提交）、`[reverted #N]`（已還原）或 `[planned, not started]`（已規劃、未開始）。沒有標籤的線索代表還沒完成，所以要加上標籤。
- **問題（Problems）。** 最多 5 個，反覆出現的那些。包括使用者一再回報的症狀，以及任何出貨後又被還原的修正，讓下一次嘗試從上一次失敗的地方開始。
- **下一步（Next move）。** 單一個最有用的下一個行動，要具體。

相鄰的功能或工單不要放進來，除非它阻擋了這一個。當摘要和線索超過一個螢幕時，先砍細節，再砍線索。用 **unslop** 技能撰寫簡報，聊天發現以 UUID 引用，共享紀錄的發現以來源引用（PR 編號、工單 ID、聊天永久連結、錯誤追蹤議題），並在任何公開輸出之前清除私人脈絡。

**回覆：** 依上述格式的簡報。
