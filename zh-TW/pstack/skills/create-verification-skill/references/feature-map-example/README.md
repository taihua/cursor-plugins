# Notes verification map（Notes 驗證地圖）

> 譯註：這是一個虛構的「Notes」筆記 app 的功能地圖範例，示範格式。指令和 UI 名稱保留英文。實際的地圖必須使用原版的英文標題。

這個資料夾是驗證 Notes 面向使用者行為時被維護的來源。操作 app 之前先讀這份索引，然後把對應的功能檔案當作做法。

## 基準前置條件

- 用一個可拋棄的資料資料夾，在 `http://127.0.0.1:4173` 啟動 Notes。
- 設定 `NOTES_DATA_DIR=/tmp/notes-verify-$RUN_ID`，讓同時進行的執行不會共享狀態。
- 預先建立標題為 `Quarterly plan` 和 `Grocery list` 的筆記。
- 把 `control-notes` 和 `notes` CLI 放進 `PATH`。
- 執行 `control-notes doctor`，並要求它回報預期的網址、資料資料夾和建置版本。
- 永遠不要操作一個不是由這次驗證執行啟動的實例。

## 操作慣例

- 除非前置條件另有說明，每份做法都從基準狀態開始。
- 偏好 ARIA 角色和無障礙名稱，而不是 CSS 選擇器或 DOM 位置。
- 把每個指令都當作字面值。引號中的名稱和旗標保持不變。
- 瀏覽器動作透過 `control-notes browser` 執行。
- 終端機動作透過 `control-notes cli -- <command>` 執行。
- 修改資料後要恢復種子資料。清理時不要移除證明用的成品。

## 證明與跳過的回報

- 擷取使用者的動作以及產生的狀態，而不只是最後的畫面。
- UI 的證明包括一份 ARIA 快照，以及一張看得到 app 身分的截圖。
- CLI 的證明包括指令、stdout、stderr 和結束碼。
- 修改資料的證明包括對儲存值的第二個唯讀檢視。
- 每個成品都要記錄使用的功能 ID 和進入點。
- 無法到達的路徑，要回報嘗試的指令和未滿足的前置條件。
- 不要把一個被跳過的進入點，回報為透過另一條路徑驗證過。

## 功能項目的格式規範

每個功能檔案以一個 H1 標題和一段描述使用者可見行為的文字開頭，然後依序使用恰好四個 H2 章節。

1. `Sub-features`（子功能）列出簡短的 ID，每個行為一行。
2. `How to get to it (user POV)`（怎麼到達，使用者視角）列出每個使用者進入點。
3. `Driving it with <harness>`（用 <測試框架> 操作）以 `Preconditions:` 開頭，並使用加標籤的項目，把每個使用者動作和一個確切的指令以及可觀察的結果配對。
4. `Gotchas`（陷阱）列出可能浪費或讓驗證執行失效的陷阱。

讓實作細節遠離地圖。只寫使用者路徑、穩定的把手、需要的狀態、指令和可觀察的證明。

## 功能

- [Create a note（建立筆記）](./create-note.md) 涵蓋瀏覽器和 CLI 的建立、取消、持久化和清理。
- [Search notes（搜尋筆記）](./search.md) 涵蓋工具列、鍵盤和 CLI 的搜尋，以及符合、空結果和清除的狀態。
