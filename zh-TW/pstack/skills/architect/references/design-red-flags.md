# Design red flags（設計紅旗）

在綜合之前篩檢每個候選。一面紅旗就是修改或拒絕這個形狀的理由。

## 淺模組（Shallow module）

淺模組暴露一個大型介面，卻只隱藏了很少的複雜度。依「公開介面背後隱藏的能力與策略」相對於「介面的大小」來判斷深度。偏好由大量行為支撐的簡單介面。

不要把深模組和深呼叫鏈混為一談。深呼叫鏈會把理解分散到各層；深模組則把能力集中在一個介面後面。

注意這些徵兆：

- 呼叫者要協調好幾個方法才能完成一個操作。
- 公開的選項暴露了內部階段或實作選擇。
- 學會介面並不能讓呼叫者免於學習實作。

## 資訊洩漏（Information leakage）

資訊洩漏讓多個模組依賴同一個內部決策。某個表示方式、策略或協議細節出現在不只一個地方，所以修改它需要協調多處修改。

公開重新匯出傳輸或線路格式的型別就是洩漏。在介面後面把外部資料解析成領域型別。讓儲存 schema、框架物件和協議細節保持私有。

## 依時間拆解（Temporal decomposition）

依時間拆解是依照執行順序、而不是它擁有的知識來組織模組。分開的載入、驗證、轉換、儲存階段，常常在好幾個邊界上重複同一個表示方式和它的不變條件。

圍繞領域知識和所有權組織程式碼。在不同時間執行的方法，只要它們保護的是同樣的決策，仍然可以屬於同一個模組。

## 直通方法（Pass-through method）

直通方法把同樣的參數轉發給另一個形狀相同的方法。它增加了一層，卻沒有隱藏任何複雜度。

移除它，或把責任移到能完成這個操作的模組。只有當轉發邊界增加了策略、轉接或一個獨特的抽象時才保留它。

## 分裂的所有權（Split ownership）

不只一個模組寫入同一份狀態，或各自保留一份副本。修改其中一個寫入者的 agent 看不到其他寫入者，所以它們的規則會逐漸分歧。

給每份狀態一個擁有者。其他模組讀取它，或請擁有者修改它。

## 一件事兩種做法（Two ways to do one task）

設計支援用不只一種方式完成同一件事。agent 會複製它最先找到的那種方式，所以每種方式都會持續增加呼叫者。

只保留一種方式。在同一個改動中，把呼叫者從其他方式移走並刪除它們。

## 可被匯入的內部（Importable internals）

呼叫者可以匯入一個模組的內部。agent 會走能編譯通過的最短路徑，所以它會直接匯入它們，它們就變成了介面的一部分。

讓內部無法從模組外部觸及，讓從外部匯入會使建置失敗。

## 手動同步的清單（Hand-synced list）

兩個以上的地方列出同樣的項目，新增一個項目就要修改每一份清單。看到其中一份清單的 agent 只會更新那一份。

只保留一份清單，其他的從它推導。如果某份清單無法推導，就讓清單不一致時建置失敗。
