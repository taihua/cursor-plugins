# Maintain a formal verification skill（維護形式驗證技能）

形式檢查證明的是它所描述的東西的性質。當程式碼改變了、驗證卻沒有，檢查可能會在它描述的是「已經不存在的程式碼」時繼續通過。這種通過才是危險的情況，因為它看起來像一個證明。這個技能是 `/create-formal-verification-skill` 產生的驗證技能，或任何針對指定程式碼執行模型檢查器、證明器或程式碼層級驗證器的專案專用技能的維護迴圈。專案專用技能處理的是 agent 在使用那個技能時所做的改動；這個技能處理的是跳過它的改動：合併、沒有使用該技能做的修改，以及跨多個 commit 累積的偏移。

## 結果

給每個檢查一個結果，並說明是哪一個：

- **in sync（同步中）**：自上次同步以來，沒有任何改動影響檢查所描述的東西，而且檢查通過。
- **updated（已更新）**：程式碼改變了，驗證現在描述的是新的程式碼，而且檢查通過。
- **bug**：驗證描述的是目前的程式碼，而程式碼違反了性質。這是關於程式碼的發現，不是偏移。
- **blocked（受阻）**：無法讓檢查重新一致，或無法執行它。確切說明原因。

一個檢查可以同時是 updated 和 bug：更新讓驗證重新描述了程式碼，然後性質在它上面失敗了。

## 修改範圍

只修改驗證：模型、測試框架、性質檔案和驗證技能本身。執行期間永遠不要修改產品程式碼，除非使用者要求。當性質在目前的程式碼上失敗時，不要為了讓它通過而削弱性質或模型。回報失敗。

## 檢查流程

1. **找到檢查。** 驗證技能沒有固定的名稱，所以依它做的事找它：一個針對指定程式碼執行模型檢查器、證明器或其他驗證器的專案技能。讀你找到的每一個，或使用者指定的那一個。對每個檢查，蒐集性質、它涵蓋的程式碼、上限與假設、執行它的指令，以及最後一次確認它描述程式碼時的 commit。如果沒有任何驗證技能，停下並指向 `/create-formal-verification-skill`。如果技能沒有記錄同步 commit，就用最後一個修改驗證檔案的 commit，並說明你這樣做了。

2. **原樣執行它。** 在改任何東西之前，每個檢查執行一次並記錄結果。這裡通過並不代表程式碼是正確的，只代表舊的描述仍然成立。這裡失敗可能是偏移，也可能是 bug。到第 5 步之前不要下判斷。

3. **讀每一個對被涵蓋程式碼的改動。** 對被涵蓋的檔案做從同步 commit 到目前 commit 的 diff，並讀每個 commit 訊息。也要找搬移過的程式碼：被改名、拆分或搬到另一個檔案的被涵蓋函式，仍然是被涵蓋的程式碼。也要找碰到某個檢查所守護之狀態的新程式碼，例如一個寫入相同欄位的新函式。對每個改動，判斷它屬於哪一種：
   - **沒有影響。** 這個改動沒有改變驗證所描述的任何東西，例如格式、註解，或驗證沒有涵蓋的程式路徑。要對照模型或測試框架檢查這一點，而不是對照 commit 訊息。
   - **驗證不再描述程式碼。** 原本是一個不可分割動作的步驟現在變成兩個、新增或移除了一個分支、某個檢查搬了位置、有新路徑到達被守護的狀態，或某個值現在有不同的範圍。模型或測試框架必須改變。
   - **承諾被刻意改變了。** 這個改動改變了程式碼所承諾的東西，而且改動中有證據說明這是刻意的：文件註解、測試、changelog 或 commit 訊息。性質必須改變，而且你必須引用那個證據。
   - **承諾可能被違反了。** 程式碼改變了，但沒有證據說明承諾改變了。把之後的失敗當作 bug 候選。

4. **依程式碼更新，而不是依結果。** 修改模型或測試框架，讓每個改變的部分再次指向審查者能打開的程式碼，並讓程式碼中一個不可分割的步驟在驗證中仍是一個步驟。在重新執行之前就依程式碼寫好更新，不要以「什麼能讓檢查通過」來塑造它。只為刻意改變的承諾修改性質。寫下舊措辭、新措辭和證據。除非改動讓上限變得錯誤，否則保持上限不變。如果你必須降低上限，在報告中說明。

5. **重新執行並評判每個結果。**
   - **通過：** 檢查現在可能是在一個已經失去失敗能力的描述上通過。用性質所防範的方式弄壞新程式碼，例如移除一個新的檢查或調換一個新步驟的順序，並確認檢查會抓到它。然後丟掉這個破壞。
   - **失敗：** 一步一步對照真實程式碼重播反例。如果某一步在程式碼中不可能發生，那就是驗證錯了。修正驗證，並說明哪裡錯了。如果每一步都可能發生，那就是 bug。指出引入它的 commit，用程式碼自己的用語把反例講成一段步驟序列，並用一句話說明危害。如果一個便宜的、針對真實程式碼的測試或重現能展示這個 bug，就把它加到報告中作為證據。不要把它提交到產品程式碼中。

6. **更新驗證技能。** 更新每個檢查涵蓋的程式碼、指令、上限、假設和同步 commit。把同步 commit 設為你檢查的那個 commit。受阻的檢查不要移動同步 commit，並在報告中說明。然後以下一個 agent 的身分照著驗證技能做一次，這樣你就知道它的步驟仍然能跑。

## 報告

對每個檢查告訴使用者：

- 結果，以及你讀過的 commit；
- 驗證中改變了什麼以及為什麼，每個改動附上簡短理由：程式碼的形狀改變了，或承諾被刻意改變了（附證據）；
- 重新執行的結果，以及你用來證明更新後的檢查仍能失敗的那個破壞；
- 每個 bug，用白話說明：以程式碼用語描述的步驟式反例、危害，以及引入它的 commit；
- 驗證仍然**沒有**涵蓋什麼，包括它應該涵蓋卻沒有涵蓋的新程式碼。

直接說出哪些失敗是驗證中的偏移、哪些是程式碼中的 bug。對於一個在你更新前通過、更新後失敗的檢查，說明舊的通過是建立在一個過時的描述上。

把驗證的更新放在它自己的改動中，和任何產品修正分開。
