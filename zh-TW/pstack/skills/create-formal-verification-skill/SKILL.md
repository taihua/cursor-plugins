# Create a formal verification skill（建立形式驗證技能）

測試檢查的是有人想到要寫的情況。形式驗證檢查的是在明確範圍內的每一種情況：模型中每一種步驟順序、到某個上限為止的每一種輸入，或每一種輸入。這個技能會找出 repo 中這件事最重要的部分，驗證它的一個性質，並留下一個專案專用技能，讓下一個 agent 能對照那個性質檢查改動。寫這個技能時，要假設讀者是一個在修改到一半時、毫無準備地讀到它、而且從沒看過你的工作的 agent。使用者必須能信任結果並據以行動，而不需要學會驗證語言。

## 從程式碼中選擇目標

從程式碼庫中找答案，只問使用者你觀察不到的事。如果使用者指定了一個區域或一個 bug，就從那裡開始。

好的目標是程式碼做出的一個承諾，一旦違反會傷害使用者，而且測試很少碰到違反它的情況。選擇 repo 中最有價值的那個目標，而不是最容易驗證的那個。

## 讓問題決定工具

選擇能以最低成本回答問題的工具：模型檢查器、證明輔助工具、以 SMT 為後端的驗證器，或其他工具。「事件會不會以錯誤順序發生」通常適合對設計的小模型使用模型檢查器，任何語言預設都用 TLA+。「程式碼本身對每種輸入是否正確」，例如記憶體安全、溢位或資料結構的不變條件，通常適合直接在程式碼上執行的驗證器。如果沒有驗證器能跑這個語言，就直說，並用自動產生的輸入去測試真正的程式碼，而不是測一個手寫的函式模型。必須在任何規模下都成立、光有上限還不夠的性質，可能需要數學證明。偏好 repo 的開發者能安裝和執行的工具，並告訴使用者你為什麼選它。

## 什麼讓它是好的

- **忠於程式碼。** 模型或證明的每個部分都指向審查者能打開的程式碼。驗證中視為一個不可分割步驟的東西，在程式碼中也是一個不可分割的步驟。名稱來自這個 repo。
- **能夠失敗。** 你從沒看過它失敗的檢查，什麼也證明不了。展示每個性質在它所守護的程式碼的一個「故意弄壞的變體」上失敗，例如移除一個檢查或調換一個步驟的順序。
- **發現就是發現。** 當目前的程式碼違反這個性質時，用程式碼的用語附上反例回報。不要削弱性質或模型直到它通過，除非使用者要求，否則不要修改產品程式碼。
- **對範圍誠實。** 說明驗證了什麼、在什麼上限和假設之下，以及什麼被排除在外。通過只涵蓋模型或上限範圍，不是整個系統。
- **不用工具也讀得懂。** 用一句白話分別說明性質和危害。把反例講成一段用程式碼用語描述的簡短步驟序列。
- **重跑成本低。** 一個指令、可重現的工具版本，以及短到讓下一個 agent 在每次相關改動時都會去跑的執行時間。
- **與程式碼保持同步。** 記錄每個檢查涵蓋哪些檔案和函式，以及你最後一次確認驗證仍描述它們時的 commit。當被涵蓋的程式碼在那個 commit 之後改變時，下一個 agent 就能看出驗證需要再檢查一次。

## 產生驗證技能

寫一個專案專用技能，它的 frontmatter 要指名區域並說明何時使用。沒有 frontmatter，技能就不會被註冊。光靠這個技能，下一個 agent 就必須能判斷一個改動是否碰到被驗證的程式碼、執行檢查、分辨真正的 bug 和建模錯誤，以及在改動是刻意的時候更新驗證。把涵蓋紀錄和同步 commit 放進技能中，並告訴下一個 agent：只有在確認驗證描述的是新 commit 的程式碼之後，才把同步 commit 往前移。使用這個 repo 真實的指令、路徑和名詞，不要留下任何佔位符。

如果檢查是一個 TLA+ 模型，告訴下一個 agent 用 pstack 的 [`/statechart`](../statechart/SKILL.md) 技能讀每個結果。它會把檢查器找到的每個不變條件違反，以白話呈現為最短路徑。當檢查通過時，`/statechart` 會畫出系統如何在各狀態之間移動的圖。用名稱提到 `/statechart` 就好。它的指令、選項和檔案路徑會隨版本和機器改變，所以不要把任何一個複製到產生的技能或它的腳本中。

## 交接前先證明

以下一個 agent 的身分，在一個「在真實程式碼中違反該性質」的暫存改動上，照著產生的技能做一次。它必須抓到這個違反。然後丟掉暫存改動，並確認檢查回到原本的狀態：通過，或只在你要回報的發現上失敗。從沒被執行過的驗證技能只是草稿。如果技能漏掉了違反，或某個步驟跑不起來，修正技能或驗證，而不是修改暫存改動。

## 交接

告訴使用者你驗證了什麼、用了哪個工具及原因、上限範圍、用白話說明檢查發現了什麼、如何執行它，以及它**沒有**涵蓋什麼。只有在你找到一個很接近的目標時，才建議第二個目標。對於沒有重新檢查驗證的改動之後要把驗證拉回同步，請使用者使用 `/maintain-formal-verification-skill`。
