### Autonomous run（自主執行）

**結束條件由你負責。定義什麼是完成，然後不停地推進到那裡。**

1. 在第一次迭代之前，把結束條件寫成一個可檢查的判定式（測試全綠、重現的問題已修好、全部 N 個 PR 已合併、像素差異為零）。
2. 用 Cursor 的 `/loop` 指令（內建功能，不是 pstack 技能）選擇喚醒機制。有事件可以監看時（CI、合併、某個 ref 前進），派一個監看子代理在事件發生時喚醒你，並以較長的定時心跳作為備案。沒有事件時，用固定間隔的心跳，間隔長度依「何時值得重新檢查結果」來決定。依「子代理」章節，為每個子代理選擇工作需要的推理等級與快速或標準速度。
3. 每次迭代做證據所能支持的最小改動，對照判定式驗證；有進展就提交，沒幫助的改動就捨棄。「可能有幫助」的雙重保險要還原，不要留著順便帶過。
   透過 **sequence-verifiable-units** 原則技能安排工作順序，驗證完每個單元再做下一個，而不是把檢查集中到最後。
4. 執行途中發現、而且有助於目標的事情歸你處理。透過 poteto-mode 自己處理壞掉的技能、相關的 bug、不穩定的驗證器、審查雜訊、工具故障、被遺棄的後續工作和可修正的偏移。範圍外的修正放進它自己的 PR。不要把可逆的工作擱著等人，也不要用 `AskQuestion`。只呈報不可逆的動作、沒有實驗能解決的真正產品或偏好判斷，或真正的死胡同。讓判定式保持為主要驅動力，每次處理完旁支修正後都回到它。
5. 每次迭代都透過 **show-me-your-work** 技能留下檢查點：一列記錄改了什麼、判定式有沒有前進。
6. 判定式達成時停下。停滯不是停止的理由，所以繼續做，並轉換做法來突破它。遇到真正的死胡同要呈報，而不是空轉；永遠不要放寬判定式來宣告勝利。

**回覆：** 結束條件、執行了幾次迭代、什麼落地了、什麼被捨棄了、判定式的最終狀態。
