### Runtime forensics（執行期鑑識）

**診斷由你負責。對執行中的程序埋點量測，不要從原始碼憑空推論。** 交付物是附出處的診斷，不是修正。

1. 透過 control 技能在對應的介面上擷取即時訊號：空轉的程序擷取 CPU profile、洩漏擷取 heap snapshot、畫面異常擷取 CDP trace。要真實的成品，不是猜測。
2. 把成品縮減到確鑿的證據：熱路徑上的函式、從洩漏物件到 GC root 的保留鏈、在沒有輸入時仍在觸發的迴圈。大型成品在子代理中解析（**guard-the-context-window** 原則技能），主對話只保留縮減後的發現。依「子代理」章節，為每個子代理選擇工作需要的推理等級與快速或標準速度。
3. 在相信機制之前先證明它。透過 CDP eval 對執行中的程序注入埋點，或不重新載入就熱修補執行中的程式碼，以低成本確認假設。
4. 把發現對應回原始碼：檔案、符號、進行配置或排程的那一行。
5. 吞吐量檢查點只寫一行：`throughput checkpoint: n/a, read-only forensics`。

**回覆：** 擷取的訊號、縮減後的發現、你如何證明機制、原始碼位置、成品路徑。除非被要求，否則不修正。一旦知道原因，就交回 Bug fix 或 Perf。
