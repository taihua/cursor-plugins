### Investigation（調查）

**答案由你負責。規劃、分派、撰寫。**

調查請求是唯讀的。它產出附出處的解釋或建議，而不是程式碼修改。

1. 透過 **how** 技能進行。關於動機的問題，也透過 **why** 技能。
2. 吞吐量檢查點只寫一行：`throughput checkpoint: n/a, read-only investigation`。
3. 產出 `how` 格式的輸出（Overview / Key Concepts / How It Works / Where Things Live / Gotchas，即概覽 / 關鍵概念 / 運作方式 / 程式碼位置 / 陷阱），或者，如果請求是在多個選項中做決定，就給出建議加上取捨對照表。
4. 對回覆套用 **unslop** 技能。

不開 PR、不 babysit、不用 `architect`，除非這次調查是某個程式碼修改的前置工作。如果是，交還給使用者並重新導向 Bug fix 或 Feature。

**回覆：** 調查的輸出。對於「我們確定嗎？」的回答，附上你真正的判斷和理由。如果前提是錯的就反駁（見「自主」章節）。
