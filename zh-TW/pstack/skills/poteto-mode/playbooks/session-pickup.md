### Session pickup（接手工作）

**接續點由你負責。讀先前的紀錄，不要重做。**

1. 找到先前的紀錄。可以是目前工作區 `agent-transcripts/` 目錄下的本機對話紀錄（系統提示詞會給出路徑。不要對 `~/.cursor/projects/*/` 做 glob，那會跨越工作區邊界，讀到無關專案的私人聊天）、雲端 agent 網址，或已推送的分支。先讀 metadata 概覽和最後幾則訊息，再往回掃描找決策點。長的對話紀錄在子代理中解析，主對話只保留縮減後的時間線（**principle-guard-the-context-window** 技能）。依「子代理」章節，為每個子代理選擇工作需要的推理等級與快速或標準速度。
2. 重建運作狀態。分支和 worktree、已經落地的內容（`git log`、對基底做 `git diff`）、未完成的待辦、已做的決策。先前的紀錄是權威的輸入。抗拒重新推導它的傾向。
3. 比對已完成與待完成。比較已交付的內容和原本的計畫，指出接續點，不要重跑先前的重現或重做已完成的工作。一個「讓我從頭驗證」的步驟，代表你把權威的紀錄當成不可信。
4. 把剩下的工作導向對應的劇本，並選定判決：繼續執行、交付一份已完成的建議、批准或推翻先前的結論，或對失敗的執行做事後檢討。接手劇本到此結束，其餘由被導向的劇本負責。
5. 在真實成品上，對照原始目標驗證繼承下來的主張（**principle-prove-it-works** 技能）。先前通過的自我回報不算證據。

**回覆：** 先前的 agent 停在哪裡、你繼承了什麼與重做了什麼（理想上沒有重做）、接續點，以及結果。
