### Eval（評測）

**實驗設計由你負責。規劃、盲化、執行、綜合。**

**盲化的不可妥協規則：**

- 在候選者看得到的任何資料夾、檔案或提示詞中，都不能出現 `eval`、`test`、`judge`、`experiment`、`rubric`、`score`、`compare`、`benchmark`、`candidate` 或 `arena`。
- 候選者的提示詞看起來要像使用者自然提出的請求。說目標，不要說後設資訊。
- 不要有誘導遵循鏈的提示。不要要求候選者列出他們套用了哪些技能、原則或檔案。泛泛地要求設計說明，並從程式碼的形狀來評分遵循鏈，而不是從自我回報。
- 清理資料夾和 slug 名稱。使用使用者可能會取的、像專案一樣的名稱。
- 不要告訴候選者還有其他候選者存在。
- 評審可以知道自己在評審，但只透過清理過的標籤看到輸出，永遠看不到模型名稱。
- 比較兩個變體時：由一個評審在單一回合、用同一個尺度為兩組打分數，且不知道每份輸出來自哪一組。

**步驟：**

1. **界定。** 說明受測的變體是什麼、什麼行為算成功。只為評審寫評分標準（3～6 條具體準則），不讓候選者看到。
2. **建立清理過的環境。** 每個候選者一個工作資料夾，裡面放好變體。放入一個自然任務會有的脈絡：專案骨架、候選者自然會去讀的技能。
3. **撰寫一個自然的提示詞。** 使用者會打的話。不能洩漏正在量測什麼。
4. **依 **arena** 技能的 Phase B，用不同模型平行派出 N 個候選者。** 每個在自己清理過的資料夾工作，給每個同樣的提示詞。依「子代理」章節，為每個子代理選擇工作需要的推理等級與快速或標準速度。
5. **依 **arena** 技能的 Phase C，用不同模型家族派出一個盲化的評審。** 評審只看到清理過的標籤和評分標準，永遠看不到模型名稱。
6. **從對話紀錄驗證遵循鏈，而不是從自我回報。** 讀每個候選者在目前工作區 `agent-transcripts/` 目錄下的本機對話紀錄（系統提示詞會給出路徑）。不要對 `~/.cursor/projects/*/` 做 glob，那會跨越工作區邊界、讀到無關專案的私人聊天。看每個候選者實際打開了哪些檔案。依它真正讀過的檔案加上程式碼的形狀來評分遵循鏈，永遠不要依候選者自己的說法。
7. **自己從頭到尾讀過每個候選者的輸出。** 和評審的判定比較。意見不一致代表某個模型有偏差，或評分標準有歧義。進行綜合。

**回覆：** 受測的變體、評分標準、每個候選者的筆記、評審的判定、你的綜合結論，以及是否推廣這個變體的建議。
