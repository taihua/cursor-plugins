# Fix Root Causes（修正根本原因）

除錯時，修正故障本身，而不是它浮現的地方。症狀是錯誤狀態變得可見的地方。根本原因是系統第一次做了它不該做的事，或沒有處理它應該處理的狀態的地方。

**為什麼：** 修症狀會藏起證據，讓故障可以在別的地方再冒出來。每一次這樣做都讓系統更難推理，因為程式碼現在帶著一個針對「沒人說得出名字的 bug」的繞路寫法。

**模式：**
- 先重現。
- 每一步都問「為什麼」，直到答案是程式碼中的一個錯誤決定，而不是更早某個錯誤的結果。
- 卡住時，就埋點量測。讀實際的錯誤和實際的狀態。不要猜。
- 問：觸發症狀的那個狀態是合理的嗎？如果系統本來就可能處於那個狀態，那麼在它上面壞掉的程式碼就是根本原因，在那裡處理這個狀態就是修正。如果那個狀態根本不應該存在，在壞掉的地方加檢查只是在藏 bug。去找出是什麼產生了那個狀態。防護、重試、吞掉錯誤、夾限數值和丟棄狀態，是藏 bug 的常見手法。
- 當某個東西只在重啟後才失敗時，先懷疑被持久化的狀態：設定檔、快取、lock 檔、序列化的狀態。
- 檢查模式，而不只是這一個實例。找出每個有同樣故障的地方，全部修好。
- 如果一個繞路寫法需要一整段註解來辯護，那就是程式碼錯了。修程式碼，不要修註解。
- 如果決定性的事實要挖得很深才找得到，就提議一個便宜、隨時開著、能讓人第一眼就看到它的訊號。
