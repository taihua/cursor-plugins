# Control-adapter contract（control 轉接器規範）

Benny 不知道如何啟動或操作每一個 app。使用者必須為目標 app 設定一個實作這份規範的 control 技能或轉接器。

把它的技能名稱設在 `control.skill_name`。

把完成的、面向使用者的功能地圖路徑設在 `control.feature_map_path`。把 [`feature-map.example.md`](./feature-map.example.md) 複製到 `.cursor/automations/benny/` 之外並填好，而不是修改被複製的範例。

如果技能、功能地圖或某個必要的能力不存在、有歧義或不完整，重現和修正工作必須安全地失敗。

## 必要的能力

### 啟動（Bring up）

在要求的測試環境中啟動要求的 app 版本。

輸入：

- Repository 和版本
- 建置或啟動模式
- 工作區、帳號、測試資料和功能狀態需求
- 成品資料夾
- 完成的功能地圖路徑

回傳：

- 工作階段識別碼
- 轉接器如何確認 app 和環境是正確的
- 穩定的 app 標記
- 之後的呼叫需要的執行中程序或目標細節
- 任何缺少的能力

轉接器必須能區分目標 app 和看起來相似的視窗、shell 或正式環境的實例。

### 操作 UI（Drive UI）

執行真實的使用者動作：

- 點擊
- 打字
- 按鍵
- 捲動
- 拖曳
- 調整大小
- 透過 app 的控制項導覽

偏好角色、標籤和穩定的選擇器。只有在一張新的截圖之後才使用座標。

回傳每個動作以及觀察到的狀態變化。

不要設定內部狀態、呼叫隱藏的 app 方法、直接寫入儲存體，或注入 DOM 變更來製造症狀。

### 操作地圖上的功能與狀態

操作 app 之前，先讀相關的功能地圖章節。

轉接器必須提供以下方法：

- 透過使用者可見的路徑瀏覽每個地圖上的功能。
- 呼叫那個功能所列出的轉接器動作名稱。
- 適用時，與預設、懸停、焦點可見、按下、停用、載入中、空白、錯誤、選中、開啟、展開以及功能特有的狀態互動。
- 透過安全的測試資料、權限、旗標、服務回應或支援的測試控制來安排某個狀態。
- 為第二次獨立的重現嘗試重設功能。
- 擷取功能地圖指名的截圖、影片和唯讀交叉檢查。

使用角色、無障礙名稱、ARIA 關係、穩定的元件標記，以及依用途命名的 data 屬性。永遠不要使用自動產生的 CSS 或 StyleX 類別、動態雜湊、子元素索引，或脆弱的 DOM 位置。

安排一個前置條件，不代表可以注入回報中的症狀。重現本身仍然必須來自真實的使用者互動。

### 檢查狀態（Inspect state）

讀取狀態以確認 UI 顯示的內容。

例如：

- 無障礙樹
- DOM 或 view 階層
- 程序狀態
- 本機 log
- 網路請求狀態
- app 公開的除錯狀態

檢查是唯讀的。如果某個查詢會改變狀態，它就屬於「操作 UI」，而且必須代表一個真實的使用者動作。

### 截圖（Screenshot）

把目前的 app 狀態擷取到要求的路徑。

回傳：

- 檔案路徑
- 擷取時間
- app 標記或視窗標題
- 簡短描述應該看得到什麼

截圖必須顯示足夠的 app 外框，以證明受測的是正確的 app。

### 錄影（Recording）

在完整的重現路徑前後開始和停止螢幕錄影。

回傳：

- 檔案路徑
- 開始和停止時間
- 擷取的視窗或區域
- 是否省略了音訊或敏感的覆蓋層

錄影必須顯示具辨識性的最終狀態，而不只是設定過程或載入畫面。

### 清理（Cleanup）

停止轉接器建立的程序和工作階段。

移除可拋棄的：

- 瀏覽器或 app 設定檔
- 暫存工作區
- 由轉接器建立的測試帳號或測試資料
- 除錯連接埠和通道
- 超過保留期限的擷取檔

回傳停止、移除、保留了什麼，或留給人處理什麼。

清理不能刪除使用者的工作。

## 轉接器的行為

轉接器必須：

- 在重現開始前回報能力。
- 回報它能操作哪些功能地圖章節、哪些受阻。
- 基準版本和打過補丁的版本使用相同的環境輸入。
- 把啟動失敗呈現為失敗。
- 限制重試次數。
- 讓機密遠離 log 和成品。
- 把擷取檔放在 repository 之外。
- 支援在兩次重現嘗試之間使用全新或重設的狀態。
- 除非使用者明確設定了安全的測試動作，否則避免對正式環境做改動。

## 環境轉譯

在宣告環境受阻之前，先用不帶平台特定名詞的方式重述缺陷，並問：同樣的行為能否在可用的環境中安全地測試？

例如：

- 指名的瀏覽器可能代表任何外部瀏覽器。
- 指名的按鍵可能代表設定的快捷鍵。
- 指名的遠端主機可能代表一個延遲或斷線的遠端目標。

只有在轉譯後的嘗試測試的是同樣的底層行為時才使用它。把它標示為轉譯後的證據。當缺少的環境本身就是缺陷的一部分時，不要把它稱為確切的重現。

硬體提示、作業系統權限對話框、只有裝置才有的 API，以及無法取得的帳號狀態，可能是真正的阻礙。

## 設定檢查

在啟用重現自動化之前，跑一次無害的轉接器檢查：

1. 啟動 app。
2. 確認穩定的 app 標記。
3. 載入一個完成的功能地圖章節。
4. 透過它的使用者路徑瀏覽到那個功能。
5. 透過地圖上的轉接器動作操作一個可拋棄的狀態。
6. 檢查產生的狀態。
7. 擷取一張截圖。
8. 錄一段短片。
9. 清理。

只有在九個步驟全部成功、而且沒有涉及任何來源頻道的 Slack 貼文時，才啟用重現工作。
