# 食譜與陷阱

值得複製的提示詞，以及每個人都會犯一次的錯誤。把路徑和完成條件換成你自己的。這些食譜刻意寫得很隨性——實際上大家就是這樣打字的，技能也讀得懂意圖。

![她正在品嚐一道完成的菜，機器人們照著食譜盒烹飪，流理台上方釘著寫有 /how、/tdd、/loop 的卡片。](../../../pstack/docs/guide/images/recipes.jpg)

## 理解一個不熟悉的子系統

```text
先用 /how 搞懂這個初始化流程怎麼運作。再用 /why 找出它最近為什麼壞掉。
```

先機制，後歷史。每個技能的報告都會告訴你它搜尋了哪些來源，讓你知道答案的根據是什麼。

## 碰程式碼前先複述雜亂的回報

```text
/poteto-mode 讀這串討論。用你自己的話、用白話複述根本問題。先不要改任何程式碼。
```

誤解會在複述時浮現，在那裡糾正只花一則訊息。在 agent 說出它自己的理解之前，先不要說出你的理論。`/in-your-own-words` 只要求複述，不走劇本。

## 送出前先磨利提示詞

```text
/sharpen 為新的帳務服務寫新人上手文件。
```

agent 會說出專家會做哪些你沒要求的事、他們會從什麼原始材料開始、用什麼方法和工具，以及有什麼外部檢查能證明結果正確。它會交回改寫成要求這些內容的提示詞，但不會做任務本身。讀起來對了再送出。

## 先做原型再挑選

```text
/poteto-mode 為設定頁的版面做幾個原型選項。放在一個切換器後面，每個都截圖給我。
```

你是從能實際運作的東西中挑選，而不是從描述中挑。agent 也會順便回答自己關於版面和時間的疑問。

## 把定案的設計轉成計畫

```text
/poteto-mode 把這個設計轉成計畫。拆成小而可驗證的 PR，每個都有自己的證明。
```

只在設計定下來之後才要求。計畫本身就是交付物，它會指出由哪個劇本來執行。

## 為一個設計取得第二意見

```text
請 /arena 針對這串討論和我們的做法提供第二意見
```

你目前的設計會變成好幾個候選之一，綜合結果會告訴你小組是找到了更好的做法，還是確認了你原本的。跟一個很難回頭的設計比起來，這個成本很低。

## 平行檢查彼此獨立的區塊

```text
/swarm 用每個套件自己的 check.sh 檢查 packages/ 底下所有套件。每個套件一個 worker，最後一份報告。
```

每個 worker 負責一個套件。主代理會等每個區塊完成，交回一份 `PASS`、`ISSUES` 或 `BLOCKED` 的報告，而不是一堆 worker 的原始輸出。

## 抱持懷疑地審查分支

```text
/interrogate 審查整個分支，但要抱持懷疑。先不要改任何東西。除非是行為上真正的 bug 或退步，否則不要挑小毛病。
```

這些限定語真的有作用。「先不要改任何東西」讓它保持唯讀；「不要挑小毛病」先過濾掉雜訊，讓經驗證的發現值得你花時間看。

## 透過會失敗的測試修 bug

```text
/poteto-mode 先重現重複寫入的問題。如果有便宜的測試路徑，就用 /tdd。然後修正並重跑。
```

「如果有便宜的測試路徑」很重要。硬是透過脆弱的 mock 寫測試，證明力不如實際跑一次指令，而劇本被允許直說這一點。

## 重現並修正回報的問題，附上證據

```text
/poteto-mode 用 /verify-<app> 重現這個問題。如果在 main 上能重現，就修好它並給我影片作為證據。
```

「如果在 main 上能重現」讓這次執行在 bug 已經消失時可以提早結束。影片讓你在讀 diff 之前就能檢查修正。

## 證明一個測試很少碰到的性質

```text
/create-formal-verification-skill 重試佇列。一則訊息絕對不能被送達兩次。
```

你會得到：一個性質在明確範圍內的每種情況都被檢查過；如果程式碼已經違反它，會有一個用你程式碼的用語描述的反例；以及一個專案技能，讓下一個 agent 在那段程式碼有任何改動時都能執行。

## 公布數字前先檢驗

```text
/benchmark-checklist 在放進 PR 描述之前，檢驗這個 40% 的加速
```

你會得到：變快、變慢、無可量測的差異、或無法判定，附上執行次數、範圍，以及限制這個數字的瓶頸。

## 不要再糾正同樣的錯誤

```text
/correct agent 一直新增設定旗標，卻沒有在 schema 裡註冊
```

修正會以架構、型別、lint 或測試的形式進入 repo，讓下一個 agent 無法再犯這個錯。

## 問怎麼做，但先不開始工作

```text
/poteto-help 怎麼讓 poteto-mode 每一輪都保持開啟？
```

你會得到一個答案、一段可以送出的提示詞，以及出處連結。在你送出那段提示詞之前，什麼都不會執行。

## 你不在時讓執行保持誠實

```text
我要去睡了，自主地繼續做，直到每份測試資料都通過。不要停。保留一份我早上可以稽核的決策紀錄。
```

完整的合約在[整夜執行那一頁](./07-overnight.md)。當任務和完成條件已經在對話中時，這個簡短版本就夠用。

## 把偏掉的執行拉回來

引導用的提示詞只要一行：

```text
我說的目標是重現。我還沒有要求修正。
```

```text
套用 prove it works。給我看真實的輸出，不是建置 log。
```

```text
/unslop 一下，不要用破折號
```

你很少需要更多字。你需要的是對的名稱，而[原則那一頁](./08-principles.md)就是你的詞彙表。

## 用白話拿到回覆

```text
/bro
```

這就是整個提示詞。[`/bro`](../../../pstack/skills/bro/SKILL.md) 會把上一則訊息用人跟人對話的方式重講一遍，沒有術語、更短。當一則回覆技術上很完整，你卻還是不知道它在說什麼時，就用它。

> 中文使用者小技巧：`/bro` 之後再加一句「用繁體中文」，就能拿到白話中文版。

## 追上一個你讓它自己跑的聊天

```text
/ketchup
```

[`/ketchup`](../../../pstack/skills/ketchup/SKILL.md) 會用白話告訴你從你上一則訊息之後改變了什麼，然後列出每一件等你決定的事，附上它的建議、證據和風險。回報的時候它不會改動任何東西。

想用「看」的方式追上，就跑 [`/ketchup-video`](../../../pstack/skills/ketchup-video/SKILL.md)。它會用一段有字幕的投影片短片呈現發生了什麼，等你決定的事則以文字列在下面。

## 陷阱

- **在提示詞裡列出技能。** 「先用 /how 再用 /architect 再用 /arena」會打亂劇本早已安排好的步驟順序。說出目標和限制就好，只有在要覆寫預設時才點名技能。
- **模糊的完成條件。** 「讓它更好」沒給 `/loop` 任何可以檢查的東西。給一個能判斷通過或失敗的指令或成品。
- **一開始就說出你對原因的理論。** agent 會往你指的地方找。先請它複述問題，再分享你的直覺。
- **採用第一個設計。** 只嘗試一次，就會鎖定模型最先想到的形狀。要求原型或用 `/architect`，根據證據挑選。
- **打磨抽象的計畫。** 對一份沒有程式碼的計畫做對抗式審查，會發明出永遠不會發生的風險。用原型解決未解的問題，再審查做出來的東西。
- **平行 agent 共用同一個 worktree。** 它們會互相覆蓋，沒人分得清哪個 agent 改了什麼。用雲端 agent 跑，或說「每個嘗試用自己的 worktree」。
- **還沒信任迴圈就開始跑迴圈。** 一個無法驗證自己成果的迴圈，只會讓未經檢查的工作來得更快。先讓驗證技能能用。
- **相信未經檢驗的數字。** 暖過的快取或被跳過的程式路徑都能偽造加速。數字在流到任何地方之前，先跑 `/benchmark-checklist`。
- **手動糾正同樣的錯誤。** 在聊天裡糾正只幫到一次執行。`/correct` 修正 repo，讓之後的執行都不會重犯。
- **用 `/arena` 來做涵蓋。** `/arena` 重複同一份設計或程式需求，再挑基底、嫁接最好的部分。`/swarm` 則是切分區塊或宣告的競賽組別，最後彙整成一份報告。
- **接受每一則審查留言。** 機器人和人都會在同一份清單裡同時提出真正的問題和雜訊。`/interrogate` 只保留重跑能證明的發現，並列出它放棄了什麼、為什麼，而你兩邊都可以推翻。
- **把 `auto` 當成模型名稱。** `auto` 和 `inherit-parent` 的意思是「不指定 model 欄位，讓子代理沿用主聊天的模型」。[設定](./01-setup.md) 有說明各個角色。
- **憑建置成功就回報成功。** 建置只證明能編譯。要求真實的指令、流程、存進去的值或效能分析，並期待回覆裡附有證據。
- **徒手寫 `SKILL.md`。** 透過[撰寫或修改技能劇本](../../../pstack/skills/poteto-mode/playbooks/authoring-a-skill.md) 來寫，這樣才會經過驗證和審查。

指南到此結束。如果你是跳著讀的，回到[設定](./01-setup.md)，跑一個真實的任務。**習慣是從使用中養成的，不是從閱讀中。**
